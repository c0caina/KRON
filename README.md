# KRON minimal

Минимальный harness для телефона с root: модель, один инструмент `console`, поле сообщения и ответ. Модель сама решает, какие команды выполнять, как работать с файлами и устанавливать программы. Нет хаба, узлов, proot, менеджера моделей, отдельных файловых инструментов, планировщика или собственной системы прав.

## Установка на телефон

Скачайте **kron-minimal.apk** из [релиза minimal](https://github.com/c0caina/KRON/releases/tag/minimal). Старый релиз `latest` содержит прежний KRON.

Это отдельное приложение **kron minimal** (`io.github.c0caina.kron`), которое не использует сервер и данные старого KRON. Установите APK, откройте и предоставьте постоянный root-доступ. Первый запуск распаковывает файлы и загружает локальную модель; это может занять время. После этого можно сразу писать сообщение, без API-ключей, подписок и выбора модели.

В комплекте LFM2.5 2.6B Q4_K_M и llama.cpp b11500. Вес модели — 1,67 ГБ, поэтому APK большой, хотя сама оболочка небольшая. Нужен свободный запас места для APK и распакованных файлов. Модель работает на CPU, 4 потока, контекст 8192 токена; скорость на конкретном телефоне нужно измерить. Стартовая модель помогает работать с устройством и настраивать среду; она не заменяет большую модель для сложной разработки.

Экран: только поле сообщения, отправка и ответ. Контекст хранится в памяти до перезапуска. Агент вызывает единственный `console` до финального ответа. Recovery и бэкапов нет.

## Файлы и подключение

При первом запуске APK копирует начальные файлы в `/data/data/io.github.c0caina.kron/files/runtime/`, затем запускает редактируемый `start.sh` от root. Старые runtime-файлы при обновлении не перезаписываются.

По умолчанию автоматически создаётся `files/kron.json`:

```json
{"base_url":"http://127.0.0.1:7792/v1","model":"ignition","api_key":""}
```

Настройки перечитываются перед каждым сообщением. Агент может сам изменить этот файл для подключения другого OpenAI-совместимого API. Экрана входа в подписки нет.

UI слушает `http://127.0.0.1:7791`, локальная модель — `127.0.0.1:7792`. Сервер принимает только loopback и проверяет Origin. Это не ограничение прав агента. `KRON_RUNTIME`, `KRON_CONFIG`, `KRON_LISTEN` задают пути и адрес.

Команды работают в новых shell: используйте явные пути или `cd`. Ввод stdin не поддерживается; длительные задачи запускайте фоном с выводом в файл. Возвращаются код выхода и stdout/stderr (до 32 КиБ каждого потока). Таймера и ограничения количества шагов нет. Root даёт права, предоставленные вашим root-менеджером; SELinux и ограничения Android сам harness не меняет.

## Самоизменение

Вне APK находятся:

- `runtime/ui/` — HTML, CSS, JS и другие файлы интерфейса. Раздаются с диска, изменения видны после обновления страницы.
- `runtime/system.md` — системный промпт, перечитывается перед каждым сообщением.
- `kron.json` — API-подключение, перечитывается перед каждым сообщением.
- `runtime/start.sh` — команда запуска на Android; можно заменить runtime или способ запуска.
- `runtime/kron` — исполняемый файл Android; новый бинарник устанавливается атомарным переименованием, затем процесс перезапускается.
- `runtime/source.tar.gz` — исходники этой сборки для дальнейших изменений. Инструменты компиляции нужно установить отдельно.

APK содержит WebView, foreground service и начальную копию файлов. Последующие обновления APK не перезаписывают runtime. Удалённые агентом файлы автоматически не восстанавливаются. Recovery, бэкапов и отката нет. После рестарта диалог в памяти теряется. Изменения интерфейса или промпта не требуют рестарта.

В системном промпте описано и обновление самого APK через root, если потребуется изменить оболочку. Для обновления поверх установленного APK нужен тот же ключ подписи. Ключ в архив исходников не включается.

На Linux соберите `cargo build --release` и запускайте бинарник рядом с папкой `runtime`, либо задайте `KRON_RUNTIME`. Локальные веса и llama-server для Linux отдельно не устанавливаются: запустите совместимый сервер самостоятельно или укажите внешний API в `kron.json`. Для обновления runtime на Android завершите launcher по PID из `runtime/pid` после ответа пользователю; сервис через несколько секунд снова выполнит `start.sh`.

## Сборка APK

Нужны Rust target `aarch64-linux-android`, NDK, JDK, Android SDK 35 / build-tools 35.0.0:

```sh
cargo build --release --target aarch64-linux-android
bash android/ignition.sh ignition-files
android/build.sh target/aarch64-linux-android/release/kron kron-minimal.apk ignition-files
```

В CI собираются Linux-бинарник и Android APK с локальной ignition-моделью, без Ubuntu. Linux-архив содержит код harness и UI, но не модель и не сервер инференса. Ветка minimal обновляет релиз `minimal`.
